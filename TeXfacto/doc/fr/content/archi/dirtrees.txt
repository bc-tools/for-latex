===================
\Structs "imposées"
===================

Un code utilisant \ttes les fonctionnalités proposées par \thisproj aura un dossier de \dev de \struct suivante.

dirtree::
    ---
    path  = ?/examples/archi/project/dirtree/start-full.txt
    title = Structure maximale
    ---


note::
    L'absence de dossier path::''doc'' pour la \mandoc vient du processus de \redac spécifique à \thisproj : voir cf::''?/src/docs.txt''.
    Il n'y a pas non plus de classique dossier path::''tests'', car les tests se feront via l'usage de \l3build dans le dossier path::''rollout'' : voir cf::''rollout.txt''.


À l'opposé, un \proj peut utiliser la \struct minimaliste ci-après où les dossiers utilisés sont les seuls obligatoires.

dirtree::
    ---
    path  = ?/examples/archi/project/dirtree/start-mini.txt
    title = Structure minimale
    ---


Les sections suivantes détaillent le rôle de chaque dossier et fichier. En voici d'abord une vue d'ensemble pour vous orienter rapidement.

    1) Le fichier path::''about.yaml'' sert à donner des \infos générales sur le \proj.

    1) Le dossier path::''readme'' permet la rédaction du fichier \readme par petits bouts.

    1) Le dossier path::''changes'' est dédié au journal complet des \chgts \techs.

    1) Le dossier path::''contrib'' accueille les \contribs éventuelles.

    1) Le dossier path::''src'' contient le code \src, mais aussi la \mandoc.

    1) Le dossier path::''tools'' accueille des scripts pour aider au \dev. Aucun \lang de \prog n'est imposé.

    1) Le dossier path::''rollout'' sera celui employé pour lancer les tests, et distribuer le projet final sur \ctan via \l3build.

    1) Le dossier path::''hooks'' permet de compléter le processus d'automatisation de \thisproj en fournissant des mécanismes d'interception codés en \python.
