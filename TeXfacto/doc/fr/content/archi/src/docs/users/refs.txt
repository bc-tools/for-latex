==================================
Un conseil pour les \refs internes
==================================

Voici une façon de nommer les \refs internes permettant d'éviter les doublons. Libre à vous de respecter, ou non, la méthodologie proposée.

    1) Un préfixe reprend le nom du \proj comme dans ''myfictproj'' par exemple.

    1) Le préfixe est complété pour identifier le dossier dans le code \src du fichier concerné pour obtenir ''myfictproj-main'' par exemple.

    1) Si la \ref est relative à une macro spéciale comme ''\mycmd'', ou un \env spécifique tel que ''\begin{myenv} ... \end{myenv}`, alors on ajoutera un autre préfixe "typé" comme dans ''myfictproj-main-macro-mycmd'' et ''fict-proj-main-env-myenv'' par exemple.

    1) Si besoin, un \id supplémentaire laissé au libre choix du codeur sera ajouté comme dans ''myfictproj-main-geo'' et ''myfictproj-main-macro-mycmd-options''. À ce stade, les éventuels conflits ne seront plus que très locaux, et donc faciles à résoudre.
