============
Pour le code
============

Pour autoriser l'usage d'un dossier en cours de \dev par un autre, les importations se font via des chemins relativement au dossier path::''src'' depuis celui en cours de \dev. Concrètement, ceci signifie que dans path::''admonitions.cls.sty'', le code \src utilise latex::''\input{../admonitions/css/bw.cls.sty}'', et non ''\input{css/bw.cls.sty}''.


warning::
    Comme \tex utilise une \struct virtuelle plane, l'emploi de ''..'' dans un ''\input'' ouvre une brèche de \secu, car le ''..'' est relatif au processus lançant \tex sur la machine de l'utilisateur final. Aïe !
    N'employer donc pas ceci pour le reste de votre code !


Lors de la \fabric du code publiable, \thisproj cherche bêtement l'emploi de latex::''\input{../*}'' pour bâtir une liste de ressources, puis construit, par défaut, le dossier suivant en aplanissant la \struct comme cela est attendu par \ctan. Noter au passage une gestion en coulisse des importations pour les adapter aux fichiers ressources renommés via un schéma évident puisque l'on passe de path::''admonitions/css/bw.cls.sty'' côté \dev à path::''admonitions.css.bw.cls.sty'' pour \ctan.

dirtree::
    ---
    path  = ?/examples/tutodoc/resources/dirtree/final/code/default.txt
    title = Le dossier par défaut du code prêt à être publié
    ---


Il se trouve que ce choix par défaut n'est pas adapté aux exigences de \ctan qui préfère avoir le contenu suivant pour éviter les collisions de noms avec d'autres \projs.

dirtree::
    ---
    path  = ?/examples/tutodoc/resources/dirtree/final/code/hook.txt
    title = Une vue simplifiée du dossier publié du code de \tutodoc
    date  = \tutodoc_date
    ---


Ce type d'assemblage ne peut s'obtenir que via le \syst d'interception du cycle de \prod proposé par \thisproj : se reporter à cf::''?/hooks/resources.txt'' pour en savoir plus. Vous apprendez aussi à ajouter de \nelles \cmds d'importation en plus de latex::''\input'' qui est gérée par défaut.
